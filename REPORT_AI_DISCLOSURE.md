# Wombat DSA Sparse Attention: AI / Agent-Assisted Development Disclosure

Author: Yury Kirpichev / Team Wombat  
Track: `dsa_sparse_attention_h16_ckv512_kpe64_topk2048_ps64`  
Submission tag: `submission-final-v2` (commit `de475b9`)

This is the appendix to `REPORT_TEMPLATE.md`. It is kept as a separate file
to keep the main process write-up at four pages while still providing a
detailed AI-use statement for reviewers who want it.

This submission was produced with substantial assistance from AI coding
agents, specifically Cursor with frontier large-language-model backends
(Anthropic Claude family and OpenAI GPT family models). The disclosure
below follows the spirit of common AI-use statements in academic and
contest venues: it states what the agents helped with, what was strictly
human-driven, and how outputs were verified.

## What the agents were used for

- Pair-programming on CUDA kernel code: drafting tile-loop skeletons,
  proposing online-softmax rescale formulations, writing WMMA fragment
  layouts, suggesting `cp.async` patterns and shared-memory overlays.
- Refactoring across the kernel: renaming, extracting helper functions,
  cleaning up dead code (for example the `WOMBAT_CUDA_GRAPH_DEBUG` and
  `WOMBAT_CUDA_GRAPH` environment-variable plumbing removal in
  `submission-final-v2`).
- Drafting and iterating on host-side machinery: the dispatcher, density
  pre-scan, split-K reducer hookup, and the CUDA graph cache lifecycle.
- Generating ablation scaffolding: Modal scripts, comparison harnesses,
  artifact log shaping, and per-phase report markdown.
- Drafting and revising the main process write-up
  (`REPORT_TEMPLATE.md`), including the Mermaid diagrams.

## What was strictly human-driven

- Choice of overall architecture (legacy / split-K / CTA-per-token), which
  hardware features to invest in, and which experiments to run.
- All performance and correctness measurements on Modal B200; the human
  author selected workloads, ran benchmarks, archived logs, and decided
  which results to act on.
- Final acceptance / rejection of every optimization. Negative results
  (head tiling, `V_PIPE` depth, BF16 logits, full warp specialization, TMA,
  Blackwell UMMA for this shape) were rejected based on measured B200
  latency, not on agent recommendation.
- All git commits, branch hygiene, and tagging (`submission-v1`,
  `submission-final`, `submission-final-v2`).
- Final correctness contract: the `abs_err` tolerance, the BF16 output /
  FP32 LSE choice, and the FP32 split-K partial decision were validated
  against measured deviations on the contest workloads.

## How agent output was verified

- Every code suggestion was compiled and run against the contest
  workloads. Builds went through `torch.utils.cpp_extension.load` with the
  `sm_100a` toolchain, and runs went through the contest benchmark harness.
- Performance claims were taken from cupti-timed Modal B200 runs (see
  "Measurement scope and limitations" on Page 4 of `REPORT_TEMPLATE.md`);
  no agent self-report of performance was used in the final report.
- Validity-relevant code paths (CUDA graph cache, density pre-scan,
  persistent scratch buffers) were re-read by the human author against
  the contest `FAQ.md` rules before the final tag.
- Documentation generated by the agent, including the main report, was
  edited by the human author for accuracy. Any number, link, or filename
  in the document is intended to be reproducible from the repository or
  its artifacts.

## Tools used

- Cursor IDE with agent-mode workflows (`Plan` / `Agent` modes) for
  exploration, refactoring, and report drafting.
- Anthropic Claude family and OpenAI GPT family models as the LLM
  backends for those agents.
- Standard open tooling for the actual submission: PyTorch
  `torch.utils.cpp_extension.load`, NVIDIA CUDA 13.2 toolchain on the
  evaluator-pinned `flashinfer/flashinfer-ci-cu132:20260401-2c675fb`
  image, Modal for B200 access, and `cupti-python` for timing.

This disclosure is included so that reviewers can interpret the
"measurement-driven" framing on Page 1 of `REPORT_TEMPLATE.md` correctly:
the *direction* of the work was human, the *typing* of the code was
substantially shared with agents, and the *acceptance criteria* for any
change were always measured B200 numbers.
